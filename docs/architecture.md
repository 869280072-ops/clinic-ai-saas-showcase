# 产品功能与技术架构

以下描述现有实现的高层关系，不包含私有源码、数据库迁移内容、环境文件或部署凭据。AI 在本文中只作为未来边界说明。

## 产品功能架构

```mermaid
flowchart TD
    P[本草云诊所管理 MVP] --> W[工作台]
    P --> A[患者档案]
    P --> V[就诊与复诊]
    P --> F[随访计划]
    W --> W1[统计与最近记录]
    A --> A1[建档 编辑 搜索 详情]
    V --> V1[初诊记录]
    V --> V2[历史参考与复诊]
    F --> F1[任务创建]
    F --> F2[状态与结果]
```

这些模块围绕同一患者关联。当前公网 Demo 为访客提供独立演示空间；基础双向隔离已由作者人工验收，不代表完整多租户权限体系。登录、角色、处方、收费和药房不在已交付功能中。

## Web 应用、业务服务与数据库

```mermaid
flowchart LR
    U[医生或工作人员] --> UI[中文 Web 页面与表单]
    UI --> N[Next.js 页面和 API 路由]
    N --> B[业务服务与输入校验]
    B --> O[Prisma ORM 与 SQLite 适配器]
    O --> DB[(SQLite 持久化数据库)]
    DB --> O
    O --> B
    B --> N
    N --> UI
    M[版本化 SQL 迁移] --> DB
```

表单通过 API 写入；服务端负责输入、关联、日期和顺序校验；数据库约束保护并发写入。页面读取同一持久化数据源，避免只在浏览器内保存展示数据。

## 实际技术选择

| 层次 | 使用技术 | 选择与边界 |
| --- | --- | --- |
| Web 框架 | Next.js 16.4.0 | 页面与 API 同一应用，需 Node.js 服务 |
| 交互与类型 | React 19.3.0、TypeScript 5.9 | 中文表单与类型约束 |
| 样式 | Tailwind CSS 4 | 管理后台与响应式布局 |
| 输入校验 | Zod | 必填、格式、日期等输入约束 |
| 数据访问 | Prisma 7.10.0、SQLite 适配器 | 实际读写与事务 |
| 持久化 | SQLite | 适合个人 MVP 的本地文件持久化；不能直接假定支持多实例生产部署 |
| 数据库升级 | 版本化 SQL 迁移 | 原子应用、校验和及数据库写入约束 |
| 验证 | Node 测试、DOM 测试、HTTP 测试、GitHub Actions | 11 项回归与构建检查，不等同于真实临床验证 |

版本沿用既有公开材料，本轮没有读取私有源码重新核定。当前独立交互 Demo 托管于 Railway，静态作品集托管于 GitHub Pages；没有已实现的模型服务、向量数据库或云消息队列，不绘制规划组件为运行链路。

## 一致性与边界

患者编号重复由服务端提示和数据库写入保护共同处理，保留旧重复档案。复诊须有前序就诊，日期不得早于最近记录；随访日期使用统一诊所时区。具体决策见 [产品决策](product-decisions.md)。

当前基础访客隔离不等同于登录鉴权、角色权限或完整多租户体系；没有完成安全审计、生产备份或高可用验收，不能将这一架构描述成生产医疗基础设施。公网服务重启后的持久化与约四小时到期清理仍待完整验证。

## 展示网站与业务系统的区别

本公开仓库的展示网站是静态 HTML/CSS 与 Markdown 文档阅读页，适合 GitHub Pages。它不启动 Next.js 业务服务，不连接患者数据库，不接收病历输入，也不提供诊疗操作。

首页仅通过外链打开 [独立 Railway Demo](https://melodious-nurturing-production-d07f.up.railway.app/demo)，不使用 iframe、不复制 SaaS 业务代码或部署配置。访客只允许使用虚构资料，演示空间有效期约 4 小时，不提供真实医疗服务。

文档中的 AI 模块尚未实现，不属于上图实际运行链路。
