# 产品功能：从建档到随访的连续业务闭环

本说明基于现有 MVP。所有示例均为**虚构演示场景**，不包含真实患者信息。状态分为“已实现”“第一版人工验收通过”“最新修复待人工回归”，避免混淆开发与验收。

## 1. 患者建档与查询

- **用户需求**：同一患者的资料有稳定入口，后续就诊不重新整理全部基础信息。
- **功能说明**：新增、编辑、按姓名或演示联系编号等信息查询，进入患者详情查看关联记录。演示编号使用 `DEMO-` 形式，不采集真实手机号作为展示资料。
- **核心操作**：新建档案 → 保存 → 成功提示 → 进入详情 → 创建初诊或设置随访。已建档患者从查询结果进入。
- **解决的问题**：基础资料和历史就诊缺少统一入口；连续点击可能重复建档。
- **实现状态**：已实现。v0.1 增加同步提交锁、禁用反馈、重复编号 409 提示及数据库并发保护。
- **验收情况**：第一版建档与查询已人工验收。最新修复通过 DOM、冲突与并发测试，尚待 Codespaces 完整人工回归。旧重复档案不自动删除或合并。

> **截图 S01 待补充**：真实运行的患者列表与档案详情；仅虚构资料，检查姓名、联系方式、浏览器地址栏及通知区域后再公开。

## 2. 初诊病历

- **用户需求**：把首次接诊的信息归属于正确患者，为以后复诊提供可查基线。
- **功能说明**：记录就诊日期、主诉、现病史、四诊/舌脉、医生评估和处理方案等内容。
- **核心操作**：进入患者详情 → 创建初诊 → 填写记录 → 保存 → 在历史中确认。
- **解决的问题**：当次记录与患者资料脱节，后续难以找回初次就诊信息。
- **实现状态**：已实现；已有就诊记录时引导创建复诊，防止重复初诊。
- **验收情况**：第一版人工验收通过；初复诊顺序与并发初诊约束有自动回归覆盖。没有自动生成诊断或处方。

> **截图 S02 待补充**：实际初诊填写界面与保存结果；内容须为虚构演示记录。

## 3. 历史查询

- **用户需求**：再次接诊前，快速找回既往主诉、评估与处理方案。
- **功能说明**：患者详情集中展示历史记录，按日期倒序查看，并可定位具体记录。
- **核心操作**：查询患者 → 进入详情 → 展开阅读对应历史 → 进入复诊。
- **解决的问题**：信息分散、重复询问和上下文丢失的产品风险；本项目尚未测量减少询问次数的效果。
- **实现状态**：已实现。
- **验收情况**：第一版人工验收通过；自动测试验证记录关联和读取。大型档案分页和性能优化不在当前交付范围。

> **截图 S03 待补充**：虚构患者的历史记录；不使用真实病历截取。

## 4. 复诊管理

- **用户需求**：在历史上下文中记录新状态，明确变化及上次方案执行情况。
- **功能说明**：保留历史参考，创建新的复诊记录，填写症状变化。新记录持续关联同一患者。
- **核心操作**：已有初诊 → 查看历史 → 创建复诊 → 填写变化与评估 → 保存。
- **解决的问题**：复诊被当成互不关联的新接诊，医生难以形成纵向记录。
- **实现状态**：已实现。日期与前序就诊顺序受到校验。
- **验收情况**：第一版人工验收通过；顺序、日期、关联及重启持久化有自动验证。

**AI 边界**：页面中的 AI 入口只解释未来规划。没有模型调用，没有自动症状比较、智能追问或医疗决策输出。

> **截图 S04 待补充**：实际复诊与历史参考界面；AI 区域须完整保留“尚未接入”说明。

## 5. 随访管理

- **用户需求**：为一次后续联系留下日期、目的与可查看的任务记录。
- **功能说明**：设置计划日期、方式和内容；可选择关联该患者的某次就诊，也可不关联具体就诊。
- **核心操作**：患者详情 → 设置随访 → 填写日期与内容 → 保存 → 在计划列表查看。
- **解决的问题**：口头安排没有统一任务入口，后续难以知道是否已联系。
- **实现状态**：已实现。关联必须属于同一患者，计划日期不能早于关联就诊。
- **验收情况**：第一版创建与展示已人工验收。最新日期处理在多个进程时区、闰日、跨年和数据库重连场景通过自动回归，人工复核待完成。

**边界**：记录“电话/线上/到院”是计划方式字段，不代表系统已接入电话、短信、微信或自动触达服务。

> **截图 S05 待补充**：随访创建与计划列表，日期应可对照。

## 6. 状态更新与结果记录

- **用户需求**：区分未处理、已完成、已取消，并知道联系后留下了什么结果。
- **功能说明**：状态为待随访、已完成、已取消；完成时须填写结果。可重新打开任务，没有自动消息发送或定时任务执行器。
- **核心操作**：打开任务 → 修改状态 → 填写结果 → 保存 → 刷新验证。
- **解决的问题**：任务列表只反映“曾安排”，没有闭环结果。
- **实现状态**：已实现；v0.1 对状态提交也复用同步锁。
- **验收情况**：第一版状态修改及刷新保留已人工验收；最新锁的状态操作仍需一起人工复核。

> **截图 S06 待补充**：一项虚构任务更新前后，隐藏任何非演示信息。

## 工作台与跨模块一致性

工作台统计来自实际数据库，展示患者、就诊、复诊与待随访概览。数据可跨页面查看，刷新及服务重启后保留。它不是商业运营报表，也没有多租户管理能力。
