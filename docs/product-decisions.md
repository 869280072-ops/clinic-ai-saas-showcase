# 从临床场景到交付：产品决策与 FDE 能力

作者具有中医学背景和基层门诊工作经验，负责本项目需求、流程、验收与迭代，使用 Codex 辅助实现。以下是个人项目中的实际决策；没有虚构访谈数量、客户上线、团队规模或商业指标。

## 决策 1：先解决记录连续性

**问题** → 一次接诊记录不等于可持续查看的患者历程；历史、复诊与随访分散时，信息需要被重新拼接。

**产品决策** → 以患者档案为中心，先把“建档—初诊—复诊—随访”串成闭环。

**实施方式** → 定义患者、就诊和随访之间的关联，按实际操作顺序组织页面和任务。

**验证证据** → 第一版核心业务及刷新持久化已经作者在浏览器操作验收。

**后续改进** → 正式用户研究、多诊所场景与任务完成时间测量尚未开展，下一步需要验证问题假设的适用范围。

## 决策 2：控制 MVP 范围

**问题** → 同时开发收费、药房、处方、权限和 AI 会使业务闭环及验证边界变得模糊。

**产品决策** → 第一版优先记录与追踪，不以“模块数量多”作为完成标准。

**实施方式** → 交付工作台、档案、就诊与随访；权限、多租户、收费和 AI 标注为后续范围。

**验证证据** → 每个核心操作可独立保存，并可通过历史和关联页面读回；用例明确覆盖正确流程和非法顺序。

**后续改进** → 扩展前重新评估用户优先级；单诊所演示不能直接推导为生产 SaaS 能力。

## 决策 3：用 Codex 辅助开发，保留产品与验证责任

**问题** → 业务意图需要转为可执行需求；生成界面不等于正确实现数据和状态逻辑。

**产品决策** → 将需求拆成有边界、可检查的开发任务，由作者验收输出。

**实施方式** → 按“目标—约束—业务流程—持久化—测试—交付记录”组织任务，使用 Codex 修改代码、运行检查并复现错误，作者进行业务判断和人工操作验证。

**验证证据** → 项目从实际数据读写发展到数据库、DOM、HTTP 回归与 CI；有明确的已完成、未完成和待验收记录。

**Agent / Workflow 边界** → 实践的是 Codex 编程 Agent 辅助的任务拆解、实现、调试与检查，以及 GitHub Actions 自动验证。现有诊所业务流程没有自主医疗 Agent 或模型编排引擎；未来的 AI 整理—证据核对—医生审核流程仍在规划。

**后续改进** → 引入需求与用例的更系统追踪；当前没有可比较的工时基线，不声称提高了某个百分比的效率。

## 决策 4：重复提交不能只靠按钮颜色

**问题** → 短时间连续触发可能发生在界面状态更新前；写入成功到页面跳转之间也存在再次提交窗口。

**产品决策** → 交互锁、业务提示与数据库约束共同保护，保留旧档案。

**实施方式** → 同步提交锁加禁用状态，保存成功后维持锁到跳转；重复演示编号返回 409；数据库层阻止新的重复写入，不自动合并、删除旧患者或病历。

**验证证据** → 自动测试覆盖同一轮渲染连续提交、失败重试、两个连接并发以及旧重复记录升级保留。

**后续改进** → 最新修复尚待完整人工回归；未来评估更完善的幂等与任务恢复设计，当前不声称具备全系统幂等框架。

## 决策 5：日期是业务日，不是浏览器所在时区

**问题** → 本地录入、云端存储与另一时区显示可能出现前后一天的偏差。

**产品决策** → 明确诊所的日历日语义，并保持录入、保存、读回和展示一致。

**实施方式** → 使用 `Asia/Shanghai` 日历日及明确时区转换，不批量改写旧记录。

**验证证据** → 自动回归包含多个进程时区、闰日、跨年及数据库重连。

**后续改进** → 新增修复需要在 Codespaces 浏览器复核；未来跨地区产品应重新设计租户时区，而不是沿用单一时区假设。

## 决策 6：将运行故障与访问入口问题分开

**问题** → 云端服务可响应，不代表本机浏览器的 localhost 就能访问它。

**产品决策** → 分别验证服务、数据和浏览器入口，不把 HTTP 200 当成完整验收。

**实施方式** → 检查监听、日志和 HTTP 响应；使用支持端口转发的环境提供实际浏览器入口；保留人工回归待办。

**验证证据** → HTTP 流程和重启持久化检查通过；作者后续完成第一版浏览器核心操作验收。

**后续改进** → 形成更完整的浏览器验收清单和可重复演示资料；公共展示站不伪装成可用业务系统。

## 决策 7：从资料整理进入 AI，而非直接给医疗结论

**问题** → 病历存在缺失、否定和前后矛盾；没有证据与审核的生成结果难以可靠使用。

**产品决策** → 未来先做可核对的结构化与变化整理，保留医生最终确认。

**实施方式** → 当前只完成规划：输出来源、缺失状态、Golden / Bad Case、失败回退和审核指标设计。

**验证证据** → 这是设计材料，不存在模型评测结果或已上线 AI 功能。

**后续改进** → 建立合成评测集和输出契约，在受控原型中验证，见 [AI 路线图](ai-roadmap.md)。
