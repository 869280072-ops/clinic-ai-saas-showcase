# 本草云 · 基层中医诊所智能管理 SaaS

**Bencao Cloud · Clinic AI SaaS**

> 从一份患者档案到一次有记录的随访，让基层诊所的连续照护有迹可循。

一个由中医学背景、具备基层门诊工作经验的项目作者独立定义需求，并使用 Codex 辅助开发的 Web 管理 MVP。它将患者建档、初诊、历史查询、复诊与随访连接成可持久化的业务闭环，为后续 AI 辅助复诊建立数据基础。

**这是求职作品集，展示产品设计、技术交付与验证过程；不是已商业部署的诊疗系统。** 本仓库只包含公开展示材料和静态展示网站，业务源码留在独立私有开发仓库。阅读本仓库不需要访问任何私有仓库。

## 业务背景：把一次接诊放回连续照护中

基层门诊的难点不只在当次记录。复诊时需要重新找回上次主诉与处理方案，随访后需要知道联系结果是否留下记录；信息一旦分散，医生就很难快速拼出完整就诊历程。

这个 MVP 以作者的临床流程经验为起点，将问题转为三个可验证的产品目标：

- **资料可找到**：围绕患者档案集中查看基本信息与历史记录。
- **复诊可对照**：填写新记录时保留历史信息参考，并记录症状变化。
- **随访可追踪**：任务具有日期、内容、状态和结果，刷新或重启后仍可读取。

这是个人项目的问题假设与设计出发点，尚未进行正式的多诊所用户研究，没有真实客户数或效率收益数据。

## 产品业务流程

```mermaid
flowchart LR
    A[患者建档] --> B[创建初诊]
    B --> C[查询历史记录]
    C --> D[创建复诊]
    D --> E[设置随访]
    E --> F[更新状态与结果]
    F --> C
```

这是典型业务主线，不是强制每步执行的工作流引擎。已有患者也可以独立设置随访。初诊/复诊顺序与随访关联仍由业务校验约束。详见 [业务流程](docs/workflow.md)。

## 系统技术架构

**实际开发栈：** Next.js 16 · React 19 · TypeScript · Tailwind CSS 4 · Prisma 7 · SQLite · Zod。

- Web 层提供中文页面和表单，Next.js 提供页面与 API 路由。
- 业务服务负责校验、就诊顺序、患者关联与持久化操作。
- Prisma 通过 SQLite 适配器访问数据库；版本化 SQL 迁移维护结构与写入约束。
- 现阶段没有 AI 模型、向量数据库或消息队列；交互 Demo 托管于 Railway，静态作品集托管于 GitHub Pages。

本公开网站另外使用轻量静态 HTML/CSS 与文档构建脚本，不运行上述业务系统。详见 [产品与技术架构](docs/architecture.md)。

## 遇到的问题与产品决策

| 问题 | 决策与实施 | 验证方式 |
| --- | --- | --- |
| 连续点击造成重复建档风险 | 同步提交锁、按钮禁用；成功跳转期间不重新开放提交 | DOM 回归测试 |
| 演示联系编号重复 | 业务层友好 409，数据库写入保护；不自动合并旧档案 | 冲突、并发与旧数据迁移测试 |
| 随访日期可能因环境时区产生偏移 | 统一使用诊所日历日与明确时区 | 跨时区、闰日、跨年和重连测试 |
| 业务源码与求职展示的公开边界 | 单独创建展示资料，不公开完整源代码及历史 | 文件清单与敏感信息检查 |

## 现阶段局限

- 最新质量修复尚待完整人工回归；没有长期多用户压测和多诊所试点数据。
- 登录、角色权限、完整多租户体系、审计日志、收费、处方、药房与生产运维尚未完成；基础访客隔离不代表安全合规认证。
- 已上线独立公众 Demo，但未作为真实医疗系统或商业系统上线。到期清理、公网服务重启后的持久化及长期稳定性仍待验收。
- 依赖维护仍有后续工作：最近开发审计保留 5 项 high，来自开发工具链；生产依赖审计快照为 0。这是一次检查结果，不是永久安全保证。
- GitHub Pages 只展示资料，交互操作发生在外部 Railway Demo；公开仓库不含 SaaS 业务代码、患者数据或私有原始日志。

## AI 能力规划：先可核对，再可采用

**以下均未实现。** 下一阶段拟以复诊资料整理为入口，设计病历结构化、症状纵向比较、信息缺口提示和有来源的风险信息整理。AI 输出应保持为候选草稿，只有医生审核确认后才考虑写入记录。

拟通过 Golden Case、Bad Case、证据定位检查和医生审核指标评价质量，而不是以“能生成文字”作为完成标准。详见 [AI 产品路线图](docs/ai-roadmap.md)。

路线：**完成 v0.1 人工回归 → 定义 AI 数据与审核契约 → 建立合成评测集 → 受控实现原型 → 小范围验证与迭代**。不承诺尚未评估的上线时间。
